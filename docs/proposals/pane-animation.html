ペインの分割・移動にアニメーションを付ける 修正案

いまは、ドロップした瞬間にペインの並びが切り替わるだけなので、どのペインがどこへ行ったのか目で追えない。下の 4 つは同じ操作を同時に再生する。ボタンを押して見比べてほしい（「ゆっくり」で 4 倍遅くなる）。

現状

アニメーションなし
一瞬で切り替わる。ペインが 3 枚以上あると、どれが動いたのか分からない。

案A 枠が飛んで着地

おすすめ
ドロップしたときの青い枠（いまの .drop-overlay と同じ見た目）が、ペインの新しい位置まで 200ms で動き、着地したペインの縁を一瞬光らせる。並び自体はすぐ切り替わるので、中身は伸び縮みしない。

案B ペインごと動かす

見た目は一番分かりやすい
全部のペインが新しい位置と大きさまで滑らかに動く。ただし本物では、動いている間ずっと会話の中身を組み直すので重い（下の比較を参照）。

案C 着地したペインだけ浮き出る

一番軽い
並びはすぐ切り替え、動いた・増えたペインだけを、来た向きから少しずらして薄い状態から出す。どこから来たかは伝わりにくい。

比較

どこへ行ったかどこから来たか重さ中身の見え方作る量
案A 枠が飛んで着地分かる分かる（ドロップの枠から続く）軽い（枠 1 枚を transform で動かすだけ）崩れない中（重ね表示 1 つ）
案B ペインごと動かす分かる分かる重い。幅・高さを毎フレーム変えると、長い会話のペインで引っかかる。transform の拡大縮小で代わりにすると文字が伸びる動いている間、文字が折り返し直す大（並べ方を絶対配置に作り替える）
案C 浮き出る分かる分かりにくい軽い崩れない小

おすすめ: 案A

  • ドラッグ中に出している「ここに入る」という青い枠が、そのまま新しいペインの位置に移るので、操作と結果がつながって見える。
  • 動くのは中身のない枠だけなので、会話が長いペインでも引っかからない。
  • 入れ替えのときは枠が 2 枚、すれ違うように動く。閉じたときは何も出さない（残ったペインが広がるだけで分かるため）。
  • OS の「視差効果を減らす」（prefers-reduced-motion）が有効なら、枠は出さずに縁を光らせるだけにする。
  • 長さは 200ms、イージングは cubic-bezier(0.2, 0, 0, 1)。光らせる縁は 600ms で消す。影・グラデーションは使わない（デザインの決まりのとおり）。

作り方（DesktopApp.tsx）

  1. ペインの外側の要素に data-pane-id を付ける。
  2. ドロップ（onDrop）で update() する直前に、全ペインの getBoundingClientRect() と、ドロップの枠（.drop-overlay）の位置を控える。
  3. useLayoutEffect で並びが変わった後の位置を読み、動いた・増えたペインについて、控えた位置 → 新しい位置へ枠を Web Animations API（element.animate）で動かす。枠は CustomPanes の上に position: fixed で重ねる。
  4. 枠が着いたら、そのペインに縁取りを重ねて薄くしていく。
// 控える（onDrop の中）
pendingFlip.current = {
  from: rectsOf(document.querySelectorAll('[data-pane-id]')),     // ペインごとの元の位置
  dropRect: overlayRef.current?.getBoundingClientRect() ?? null,  // ドロップの枠
  moved: paneId ?? null,                                         // 動かしたペイン（新規なら null）
};

// 並びが変わった後
useLayoutEffect(() => {
  const f = pendingFlip.current; pendingFlip.current = null;
  if (!f) return;
  for (const el of document.querySelectorAll<HTMLElement>('[data-pane-id]')) {
    const id = el.dataset.paneId!, to = el.getBoundingClientRect();
    const from = f.dropRect ?? f.from.get(id);     // ドロップの枠から飛ばす
    if (!from || (id !== f.moved && f.from.has(id))) continue; // 動いた・増えたペインだけ
    flyGhost(from, to).then(() => flashPane(el));
  }
}, [layout]);
あわせて直したい点: いまの CustomPanes は「列 → 行」の入れ子で描いているため、ペインを別の列へ動かすと React がそのペインを作り直し、会話のスクロール位置が先頭に戻る（列をまたぐ入れ替えも同じ）。これも「どうなったか分かりにくい」原因になっていると思われる。案A とは別に、ペインを列の外で key を保ったまま描く形（CSS Grid か絶対配置）に変えると直せる。案B を選ぶ場合はこの作り替えが前提になる。
