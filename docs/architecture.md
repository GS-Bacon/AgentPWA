# AgentPWA アーキテクチャ

iPhone / iPad / Web から、Claude と Codex の複数セッションを同時に操作する PWA です。返答待ちのセッションを優先して表示します。

- プロトコル: [docs/protocol.md](protocol.md)

## 1. 全体構成

```
 iPhone / iPad / ブラウザ (PWA)
        │ HTTPS + WebSocket（tailscale serve 経由、tailnet 内のみ）
        ▼
 ┌──────────── Hub（いまはこのPC）──────┐
 │ 127.0.0.1 で待ち受け                  │
 │ セッション管理 / SQLite / Web Push    │
 │ ├─ driver-claude ─┐                   │
 │ └─ driver-codex  ─┴─ 起動役（Launcher）│
 └───────────────────────┬──────────────┘
          ├─ local: このPCで子プロセスとして起動
          └─ ssh:   ssh <host> -- claude -p … / codex app-server
                    （SSH 先の Ubuntu など。CLI はそのマシンで動く）
```

- CLI が動くマシンと作業フォルダの組を「プロジェクト」と呼びます。詳しくは「6. プロジェクトとマシン」を参照してください。

- **課金**: どちらのエージェントも、ユーザー自身がログインした CLI をそのまま動かします。Claude は Pro/Max、Codex は ChatGPT プランの枠で動かします。API キーによる従量課金は使いません（Claude Agent SDK を使わないのはこのためです）。
- **公開範囲**: `tailscale serve` だけで公開します。インターネットに公開する `tailscale funnel` は使いません。

## 2. ディレクトリと担当

| パス | 内容 | 担当 |
|---|---|---|
| `packages/shared/` | 共通の型（[protocol.ts](../packages/shared/src/protocol.ts)） | **共同**（変更は合意制） |
| `packages/hub/` | サーバー本体（セッション管理、保存、配信、Push、認証） | Claude |
| `packages/web/` | PWA（React + Vite） | Claude |
| `packages/web/src/agents/codex/` | Codex 固有の表示部品（差分ビューなど、必要な場合のみ） | Codex |
| `packages/driver-claude/` | Claude CLI ヘッドレスの Driver | Claude |
| `packages/driver-codex/` | Codex app-server の Driver | Codex |
| `docs/` | 設計文書 | 共同（自分の担当部分を書く） |

運用のルール:
- 自分の担当外のファイルは変更しない。必要な変更は、相手への依頼として PR の説明か Issue に書く。
- `packages/shared/` の変更だけを含む PR を、先に単独で出す（ブランチ名は `protocol/*`）。マージするかはユーザーが判断する。
- ブランチ名は担当ごとに `claude/*`、`codex/*` とする。
- 各担当は相手の作業を待たなくてよい。Driver はフィクスチャ（JSONL）と `scripts/try.ts` で単体で開発し、Web はフィクスチャを流し込んで表示を作る。

## 3. 技術スタック

- Node.js（現行 LTS）+ TypeScript、npm workspaces、ESM
- Hub: Fastify + WebSocket、SQLite（better-sqlite3）、Web Push（VAPID）
- Web: React + Vite + vite-plugin-pwa、ダークテーマ固定
- 常駐化: 最初は手動起動。後で Windows のタスクスケジューラかサービスに登録する

## 4. 表示の優先順位

1. 許可／承認待ち（`waiting_approval`）
2. 質問待ち（`waiting_input`）
3. 完了・未読（`idle` かつ未読。既読管理は Hub）
4. 実行中（`running` / `starting`）
5. アイドル・停止（`idle` で既読、`error`、`stopped`）

同じ順位の中では、待ちが長い順に並べます。状態が 1〜3 に変わったら Web Push で通知し、アプリアイコンにバッジを付けます。

## 5. 画面構成

- **iPhone**: 下部タブで Claude / Codex / 設定 を切り替えます。一覧から詳細へは、1画面ずつ遷移します。
- **iPad / Web**: ペインを何枚でも並べられます。
  - レイアウトは「1列・2列・3列・2×2」から選べ、Web ではさらに境界をドラッグして自由に分割できます。
  - iPad で画面に収まらないペインは、横スワイプで表示します。
  - 「次の待ちへ」（Web は Alt+J）で、待っているペインに順番にフォーカスが移ります。
  - 左の一覧から、セッションをペインへドラッグして配置します。
- **権限モードの切り替え**（全端末共通）: ペインの入力欄の左に、現在のモード（「毎回確認」「編集は自動」「自動承認」「すべて自動」「計画のみ」）を出すボタンを置きます。押すとメニューが開き、実行中・許可待ちのどの状態でも切り替えられます。Web では Shift+Tab でも順に切り替えます（「すべて自動」は確認が要るので、Shift+Tab の巡回には入れません）。
  - 「自動承認」は、エージェント側の安全判定が操作ごとに許可を決め、危険と判定した操作だけ止めるモードです。メニューに「安全と判定した操作は確認せずに実行します」と説明を添えます。フォルダの制限はありません。エージェントやプランの都合で使えないときは、切り替えに失敗した旨をペインに出し、元のモードのままにします。
  - 「すべて自動」は、プロジェクトの設定で許可したプロジェクトのセッションでだけ選べます（他のプロジェクトでは無効表示）。選ぶときは確認を1回挟みます。
  - 「すべて自動」のセッションは、一覧の行とペインのヘッダーに「⚠ 自動」と黄色（`#d29922`）の文字で示します。
  - 新規セッションの開始画面でも、モードを選べます。
- **新規セッション**: プロジェクトを選んで開始します。開始画面から新しいプロジェクトも作れます（6.3）。一覧の行とペインのヘッダーには「プロジェクト名 · マシン名」を出します（このPCのプロジェクトはマシン名を省きます）。
- **セッションのアーカイブと削除**（全端末共通。Claude のデスクトップアプリ・スマホアプリと同じ考え方）
  - 操作する場所: iPhone は一覧の行を左にスワイプして「アーカイブ」「削除」を出します。iPad / Web は、一覧の行の右クリック（iPad は長押し）とペインのヘッダーの「⋯」メニューから選びます。
  - **アーカイブ**: 一覧から外し、一覧の末尾の「アーカイブ済み（件数）」に畳んで入れます。履歴は残り、開いて読めます。「アーカイブを解除」で一覧に戻し、送信すれば続きから再開します。確認は挟まず、画面下に「元に戻す」を数秒出します。
  - **削除**: Hub の記録（会話とイベント）と、エージェント側の履歴（Driver が対応していれば）を消します。元に戻せないので、「このセッションを削除します。元に戻せません」と確認を1回挟みます。削除ボタンの文字はエラー色（`#f85149`）にします。
  - 実行中・許可待ち・質問待ちのセッションは、Hub がエージェントを止めてからアーカイブ・削除します。このときは確認で「実行中のセッションを止めます」と添えます。
  - アーカイブ・削除したセッションを開いているペインは、すべての端末で閉じます（ペインの並びの自動保存からも外します）。未読・待ちの件数とアプリアイコンのバッジも数え直します。
  - アーカイブ済みのセッションは、自動では削除しません。

## 6. プロジェクトとマシン

### 6.1 用語

| 用語 | 中身 |
|---|---|
| マシン | CLI（`claude` / `codex`）が動く場所。接続方法は `local`（Hub と同じPC）と `ssh`。後で `runner` を足せるようにしておく |
| プロジェクト | マシン＋そのマシン上のフォルダ＋使う AI（Claude / Codex のどちらかに固定）＋名前＋設定 |
| セッション | 必ず1つのプロジェクトに属する |

これまでの「フォルダの許可リスト」は、プロジェクトに置き換えます。セッションは、登録したプロジェクトでだけ起動できます。

### 6.2 マシン

- 持つ項目: ID（Hub が採番し、変えない）、表示名、接続方法（`local` / `ssh`）、SSH のホスト名、OS（`windows` / `linux` / `macos`）、プロジェクトを作ってよいルートフォルダ（複数可）、CLI の起動コマンド（省略時は既定値）。
- ID と接続方法を分けて持つのは、Hub を別のPCへ移すためです（6.5）。プロジェクトとセッションはマシンの ID だけを持ち、接続方法は持ちません。
- SSH は、Hub のPCの OpenSSH クライアント（Windows 標準の `ssh.exe`）を使います。
  - ホストは `~/.ssh/config` の `Host` 名で指定します。認証は鍵と ssh-agent だけにし、Hub はパスワードや秘密鍵を保存しません。
  - `BatchMode=yes` を付け、パスワードやホスト鍵の確認を求められたら失敗させます。ホスト鍵の確認は省きません。初めてのホストは、ユーザーがターミナルで一度 `ssh` して登録します。
  - `ServerAliveInterval` を付けて、切断を早く検知します。
- 接続の確認: Hub はマシンごとに、つながるか、CLI があるか、ログイン済みか（`checkAuth`）を確かめ、マシンの一覧に「● 接続中」「● 未ログイン」のように示します。
- パスは、マシンの OS に合わせて扱います。Hub が Windows でも、Linux のマシンのパスは POSIX として扱います（`path.posix`）。

### 6.3 プロジェクト

- 持つ項目: ID、名前、マシンの ID、フォルダ（そのマシン上の絶対パス）、使う AI（`claude` / `codex`。プロジェクトごとに固定）、`full_auto` を許すか、既定の権限モード。
- MVP では、Hub の設定ファイルの `folders` がプロジェクトにあたります（マシンはこのPCだけ）。フェーズ3で画面から作れるようにし、保存先を SQLite に移します。そのとき `folders` は読み込んで移します。
- 作る場所: 設定タブの「プロジェクト」と、新規セッションの開始画面。
- 作る手順:
  1. マシンを選ぶ（接続状態を ● で示す。つながらないマシンは選べない）
  2. 作り方を選ぶ
     - 既存のフォルダを選ぶ: マシンのルートフォルダの下を、Hub 経由で見て回って選ぶ
     - 新しいフォルダを作る: 名前を入れて作る。`git init` も選べる
     - `git clone`: URL を入れて、ルートフォルダの下に clone する
  3. 名前、使う AI、設定（`full_auto` を許すか、既定の権限モード）を決める。使う AI は、そのマシンで CLI が使えてログイン済みのものだけ選べる
- フォルダは、マシンのルートフォルダの下にあるものだけ使えます。Hub は、パスの正規化とシンボリックリンクの解決をしたうえで、ルートの外に出ていないかを、そのマシン上で確かめます。
- プロジェクトを外すと、そのプロジェクトのセッションはすべてアーカイブします。フォルダとエージェント側の履歴は消しません。

### 6.4 SSH 先での実行

- CLI は SSH 先で動かします。CLI の Bash やテストを SSH 先で動かすためです（このPCで CLI を動かして、ファイルだけを SSH で触る方式は採りません）。
- Hub は `ssh -T <host> -- <起動コマンド>` を子プロセスとして起動し、その標準入出力を Driver に渡します。Claude の stream-json も Codex app-server の JSON-RPC も標準入出力でやりとりするので、Driver は SSH を意識しません。
  - 起動コマンドは、作業フォルダへ移ってから CLI を起動します（`cd <フォルダ> && exec claude …`。値はシェル用に必ずクォートする）。
  - SSH の非対話シェルでは `~/.bashrc` の PATH が読まれないことがあるため、既定ではログインシェル（`bash -lc`）で起動します。CLI の場所はマシンの設定で直接指定することもできます。
- ログイン: CLI は、そのマシンでログインした状態を使います。サブスクリプション前提（API キーを使わない）は SSH 先でも同じで、`checkAuth()` は SSH 先で実行します。
  - 最初に使う Ubuntu のマシンは、Codex はログイン済みです。Claude は、`claude` を入れて一度ログインしておく必要があります。
- 許可要求: Hub 内の MCP ツールには SSH 先の CLI から届かないため、Claude の許可要求は標準入出力の制御メッセージで受けます（docs/protocol.md の Claude の対応表）。ローカルでも同じ方式にそろえます。
- 切断: SSH が切れると CLI も終わります。Driver は `error`（`fatal: false`）と `status: stopped` を送ります。次に送信したとき、Hub が `resumeToken` で再開します（会話の履歴は SSH 先に残っています）。実行中のターンは切断で途切れます。長時間の作業で困るようなら、後で Runner（常駐プロセス）を足します。
- 履歴の削除（`deleteHistory`）は SSH 先のファイルを消すので、これも起動役を通して実行します。

### 6.5 Hub の置き場所と移設

- 当面、Hub はこのPC（常時起動）に置きます。将来、別のPCへ移せるようにしておきます。
- 移せるようにするための決まり:
  - Hub の状態（SQLite、設定、VAPID 鍵）は、1つのデータフォルダにまとめます。場所は環境変数で変えられるようにし、移設はこのフォルダのコピーで行います。
  - Hub のコードには、このPC固有のパスや Windows 前提を入れません。
  - マシンの接続方法だけを変えれば移せるようにします。移設後は、新しい Hub のPCを `local` に、元のPCを `ssh` に切り替えます（元のPCが Windows なら OpenSSH サーバーを有効にします）。プロジェクトとセッションはそのまま使えます。
- 移設で変わるもの: PWA の URL（`tailscale serve` のホスト名）が変わるので、ホーム画面の PWA を入れ直し、Web Push の通知を許可し直します。
- Hub を複数置いて同期することはしません。PWA の接続先は常に1つです。

### 6.6 共通プロトコルへの変更案（v4、未提出）

`packages/shared` を変えるため、`protocol/*` ブランチの PR として別に出します。

- Driver に「起動役（`ProcessLauncher`）」を渡します。起動役は `local` なら `child_process`、`ssh` なら `ssh` で子プロセスを起動し、標準入出力を返します。Driver は子プロセスを自分で起動せず、必ず起動役を使います。
- `checkAuth`、`start`、`deleteHistory` に起動役を渡します（`checkAuth` はマシンごとに呼ぶことになります）。
- 起動役は OS（パスの扱い）も Driver に知らせます。
- docs/protocol.md の「フォルダの許可リスト」という言い方を「プロジェクト」に改めます。
- Codex への依頼: `driver-codex` で、子プロセスの起動を起動役に置き換えてください。

## 7. セキュリティ

- Hub は `127.0.0.1` でのみ待ち受け、`tailscale serve` が中継します。
- serve が付ける `Tailscale-User-Login` ヘッダーを確認し、許可したユーザー以外は拒否します。
- Tailscale の ACL で、Hub のポートに届く端末を自分の端末に限定します。
- セッションは、登録したプロジェクトでだけ起動します。プロジェクトのフォルダは、マシンごとに決めたルートフォルダの下に限ります（6.3）。
- SSH は鍵認証だけを使い、Hub はパスワードと秘密鍵を保存しません。ホスト鍵の確認は省きません（6.2）。
- 権限モードの既定は「毎回確認」です。
- 「すべて自動」（`full_auto`）は、プロジェクトの設定で個別に許可したプロジェクトだけで使えます。Hub がこの制限を守り、許可のないセッションへの切り替えは拒否します。
- 「自動承認」（`auto`）は、危険と判定された操作をエージェント側で止めるため、フォルダの制限を設けません。
- 削除はエージェント側の履歴も消し、元に戻せません。Hub の削除 API は1件ずつ受け付け、一括削除は作りません。

## 8. フェーズ

1. **MVP**: このPCのみ。Claude と Codex それぞれで、複数セッション・優先表示・許可操作ができる。iPhone 表示と、iPad/Web の複数ペイン表示。ペインの並びは端末ごとに自動保存し、次に開いたときに復元する。セッションは最初からプロジェクト（`local` のマシンだけ）で起動し、Driver も起動役を通して子プロセスを起動する（後で SSH を足すときに作り直さないため）。
2. Web Push、再起動後の再開、差分表示
3. SSH のマシンとプロジェクトの管理画面（作成・`git init`・`git clone`）
4. 常駐化
5. Runner（SSH の切断で困るようになったら）

## 9. 見送った機能

- **ワークスペース**（ペインの並びと各ペインのセッションに名前を付けて保存し、切り替える機能）は MVP に入れない。必要になったら追加する。

## 10. デザインの決まり

- 配色は GitHub の Primer（`@primer/primitives` 11.10.0）の dark テーマのトークン値を使う。

| 用途 | 値 |
|---|---|
| 背景（本文） | `#0d1117`（bgColor-default） |
| 背景（ヘッダー・サイドバー・ユーザー発言） | `#151b23`（bgColor-muted） |
| 背景（入力欄・コード） | `#010409`（bgColor-inset） |
| 通常ボタン | 背景 `#212830`、枠 `#3d444d` |
| 主ボタン（許可・送信・開始） | 背景 `#238636`、文字 `#ffffff` |
| 境界線 | `#3d444d` |
| 文字 | `#f0f6fc`、補助 `#9198a1` |
| 許可／承認待ち | `#d29922`、強調面 `#bb800926`、枠 `#9e6a03` |
| 質問 | `#ab7df8` |
| 完了・未読 | `#4493f8` |
| 実行中 | `#3fb950` |
| エラー・削除行 | `#f85149` |
| Claude の識別色 | `#db6d28` |
| Codex の識別色 | `#4493f8` |

- 形はシンプルにする。角丸は、ボタン・入力欄・コード枠など操作部品だけに 6px（件数バッジは 3px）を使い、一覧・ペイン・パネルは角丸なしにする。
- 影、グラデーション、丸いピル型のラベルは使わない。状態は「● 許可待ち」のように、色付きの点と文字で表す。
- 一覧はカードを並べず、区切り線のある行で表示する（VS Code のサイドバーに近い密度）。
- 待っているペインは、ヘッダー上端に 2px の黄色の線を引いて示す（VS Code のアクティブタブと同じ表現）。
