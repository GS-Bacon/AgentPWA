# AgentPWA アーキテクチャ

iPhone / iPad / Web から、Claude と Codex の複数セッションを同時に操作する PWA です。返答待ちのセッションを優先して表示します。

- プロトコル: [docs/protocol.md](protocol.md)

## 1. 全体構成

```
 iPhone / iPad / ブラウザ (PWA)
        │ HTTPS + WebSocket（tailscale serve 経由、tailnet 内のみ）
        ▼
 ┌──────────── Hub（いまはこのPC）──────┐
 │ 127.0.0.1 で待ち受け                  │
 │ セッション管理 / SQLite / Web Push    │
 │ ├─ driver-claude ─┐                   │
 │ └─ driver-codex  ─┴─ 起動役（Launcher）│
 └───────────────────────┬──────────────┘
          ├─ local: このPCで子プロセスとして起動
          └─ ssh:   ssh <host> -- claude -p … / codex app-server
                    （SSH 先の Ubuntu など。CLI はそのマシンで動く）
```

- CLI が動くマシンと作業フォルダの組を「プロジェクト」と呼びます。詳しくは「6. プロジェクトとマシン」を参照してください。

- **課金**: どちらのエージェントも、ユーザー自身がログインした CLI をそのまま動かします。Claude は Pro/Max、Codex は ChatGPT プランの枠で動かします。API キーによる従量課金は使いません（Claude Agent SDK を使わないのはこのためです）。
- **公開範囲**: `tailscale serve` だけで公開します。インターネットに公開する `tailscale funnel` は使いません。

## 2. ディレクトリと担当

| パス | 内容 | 担当 |
|---|---|---|
| `packages/shared/` | 共通の型（[protocol.ts](../packages/shared/src/protocol.ts)） | **共同**（変更は合意制） |
| `packages/hub/` | サーバー本体（セッション管理、保存、配信、Push、認証） | Claude |
| `packages/web/` | PWA（React + Vite） | Claude |
| `packages/web/src/agents/codex/` | Codex 固有の表示部品（差分ビューなど、必要な場合のみ） | Codex |
| `packages/driver-claude/` | Claude CLI ヘッドレスの Driver | Claude |
| `packages/driver-codex/` | Codex app-server の Driver | Codex |
| `docs/` | 設計文書 | 共同（自分の担当部分を書く） |

運用のルール:
- 自分の担当外のファイルは変更しない。必要な変更は、相手への依頼として PR の説明か Issue に書く。
- `packages/shared/` は直接変えてよい。変えたら docs/protocol.md の変更履歴に追記し、相手側の対応が要るものは docs/protocol.md の依頼の節に書く。
- ブランチ名の決まりはない（専用のブランチや PR を作らなくてよい）。
- 各担当は相手の作業を待たなくてよい。Driver はフィクスチャ（JSONL）と `scripts/try.ts` で単体で開発し、Web はフィクスチャを流し込んで表示を作る。

## 3. 技術スタック

- Node.js（現行 LTS）+ TypeScript、npm workspaces、ESM
- Hub: Fastify + WebSocket、SQLite（Node 組み込みの `node:sqlite`。ネイティブモジュールのビルドや install スクリプトが要らないため better-sqlite3 から変更）、Web Push（VAPID）
- Web: React + Vite + vite-plugin-pwa、ダークテーマ固定
- 常駐化: 最初は手動起動。後で Windows のタスクスケジューラかサービスに登録する

## 4. 表示の優先順位

1. 許可／承認待ち（`waiting_approval`）
2. 質問待ち（`waiting_input`）
3. 完了・未読（`idle` かつ未読。既読管理は Hub）と、「未読にする」で印を付けたもの（`idle` / `error` / `stopped`）
4. 実行中（`running` / `starting`）
5. アイドル・停止（`idle` で既読、`error`、`stopped`）

同じ順位の中では、待ちが長い順に並べます（5 の「アイドル・停止」は待ちではないので、最近動いた順にします）。状態が 1〜3 に変わったら Web Push で通知し、アプリアイコンにバッジを付けます。

**ピン止めと未読の印**: セッションのメニュー（ペインの「⋯」、一覧の行の右クリック・長押し、iPhone は行の左スワイプ）から、ピン止めと「未読にする / 既読にする」を切り替えられます。どちらも Hub が記録し、全端末で共有します。

- ピン止めしたセッションは、上の順位にかかわらず一覧の先頭に出します（ピン止めの中も上の順位で並べます）。行に画鋲の印を出し、iPhone では「ピン止め」の見出しにまとめます。
- 「未読にする」の印は、そのセッションを開いて既読にする（フォーカスを移して開き直す、または新しい内容が届く）と外れます。印を付けたペインをそのまま見ていても、すぐには外しません。

**一覧の件数の制限**: セッションが多いときは、プロジェクトごと（iPhone はアイドルの欄）とアーカイブ済みの欄で、最初の 10 件だけ出し、末尾の「さらに表示（残り N 件）」で 10 件ずつ増やします。ピン止め・あなたの番・実行中と、ペインに出しているセッションは、件数に関係なく出します。何件まで出すかは画面を開いている間だけ覚えます。

## 5. 画面構成

セッションは **プロジェクト（作業フォルダ）** ごとにまとめます。プロジェクトは Hub の設定ファイルの folders（許可リスト）そのもので、その順に並べます。使う AI（Claude / Codex）は **プロジェクトごとに固定** します（folders の `agent`）。セッションごとには選ばず、新しいセッションはプロジェクトを選ぶだけで始めます。AI はプロジェクト名の横のアイコン（Claude は橙の吹き出し、Codex は青の `</>`）で示します。

同じフォルダを Claude と Codex の両方で使うことがあるので（例: 同じリポジトリを両方の AI で触る）、プロジェクトは **フォルダと AI の組** で1つとします。同じフォルダを、AI ごとに1つずつ別のプロジェクトとして登録できます（同じ AI で2つは不可）。一覧には別のプロジェクトとして並び、アイコンで見分けます。並び順・色・既定の権限モード・`full_auto` の許可も、プロジェクトごとに別です。

- **iPhone**: 下部タブで「セッション / 設定」を切り替えます。上部にプロジェクトのタブ（すべて / 各プロジェクト。AI のアイコンと待ちの件数付き、横スクロール）を出し、選んだタブのセッションを「ピン止め / あなたの番 / 実行中 / アイドル」の順に並べます。セッションの詳細へは、1画面ずつ遷移します。
- **iPad / Web**: 左の一覧はプロジェクトごとの折りたたみ式で、プロジェクト名の横に AI のアイコン、待ちの件数、「＋（このプロジェクトで新しいセッション）」を出します。ペインを何枚でも並べられます。
  - ペインの並べ方は VS Code のエディターグループと同じ操作にします（レイアウトの切り替えボタンや分割ボタンは置きません）。ペインの見出しをドラッグして、ほかのペインの上下左右の端に落とすとその位置に分割し、中央に落とすと2枚を入れ替えます。ドラッグ中は、落とすと新しいペインが入る範囲（分割なら半分、中央なら全体）を半透明の青い四角で示し（分割のときは元のペインが残る側も薄い点線の四角で示す）、その中に「右に分割」「入れ替え」「このペインに表示」などの文字を出します。iPad は見出しの長押しで掴みます。
  - 境界をドラッグすると幅・高さが変わり、境界をダブルクリックすると均等になります（列の境界は全列の幅、行の境界はその列の中の高さ）。
  - ペインの番号（Alt+1〜9）は、見た目の順（左の列から、列の中は上から）に振ります。
  - 画面に収まらないときは、横スクロール（iPad は横スワイプ）で表示します。
  - 「次の未読へ」（Web は Alt+J）で、未読のセッション（確認待ちを含む）に順番に移ります。「確認待ちへ」（Web は Alt+K）は、許可・質問のカードが出ているセッションだけを回ります。ペインの見出しの上端の色も、カードが出ているときだけ付けます。
  - 左の一覧でセッションを選ぶと、新しいペインで開きます（フォーカス中のペインの右に足す）。すでにどこかのペインに出ていればそこへ移り、フォーカス中のペインが空ならそこに表示します。「次の未読へ」「確認待ちへ」は、これまでどおりフォーカス中のペインで切り替えます（ペインを増やし続けないため）。
  - 左の一覧から、セッションをペインへドラッグして配置することもできます。中央に落とすとそのペインに表示し、端に落とすとその位置に新しいペインを作ります。
  - Esc で、フォーカス中のペインのセッションを中断します（入力欄の中断ボタンと同じ）。メニューやダイアログが開いているときの Esc は、それを閉じるだけにします。
- **権限モードの切り替え**（全端末共通）: ペインの入力欄の左に、現在のモード（「毎回確認」「編集は自動」「自動承認」「すべて自動」「計画のみ」）を出すボタンを置きます。押すとメニューが開き、実行中・許可待ちのどの状態でも切り替えられます。Web では Shift+Tab でも順に切り替えます（「すべて自動」は確認が要るので、Shift+Tab の巡回には入れません）。
  - 「自動承認」は、エージェント側の安全判定が操作ごとに許可を決め、危険と判定した操作だけ止めるモードです。メニューに「安全と判定した操作は確認せずに実行します」と説明を添えます。フォルダの制限はありません。エージェントやプランの都合で使えないときは、切り替えに失敗した旨をペインに出し、元のモードのままにします。
  - 「すべて自動」は、プロジェクトの設定で許可したプロジェクトのセッションでだけ選べます（他のプロジェクトでは無効表示）。選ぶときは確認を1回挟みます。
  - 「すべて自動」のセッションは、一覧の行とペインのヘッダーに「⚠ 自動」と黄色（`#d29922`）の文字で示します。
  - 新規セッションの開始画面でも、モードを選べます。既定は「自動承認」です（プロジェクトの設定で変えられます）。
- **モデルとエフォートの切り替え**（全端末共通）: ペインの入力欄の上に、現在のモデルとエフォート（例: 「Opus · エフォート 高」。どちらも既定なら「既定のモデル」）を出すボタンを置きます。押すとメニューが開き、「モデル」（既定 / Opus / Sonnet / Fable / Haiku）と「エフォート」（既定 / 低 / 中 / 高 / 超高 / 最大）を、実行中・許可待ちのどの状態でも切り替えられます。切り替えると会話に「モデルを「…」にしました」と1行出します。新規セッションの開始画面でも選べます。選べる項目は AI ごとに決め、Codex の選択肢は Codex 担当の対応表に合わせます。
- **入力欄**（全端末共通。Claude のデスクトップアプリに合わせる）
  - **ファイルの添付**: 入力欄の左のクリップのボタンで選ぶほか、スクリーンショットなどの画像を貼り付ける、ファイルをペインにドロップする、でも添付できます。送る前は入力欄の上にファイル名（画像は小さなサムネイル）を出し、× で外せます。送った発言の下にはファイル名を出します。大きな画像は長い辺 2000px までに縮めて送ります。
  - **スラッシュコマンド**: 先頭に `/` を打つと、そのプロジェクトで使えるコマンド（組み込み・スキル・`.claude/commands`）の候補を入力欄の上に出します。↑↓ で選び、Tab か Enter で補完、Esc で閉じます（名前を打ち終わっていれば Enter でそのまま送信）。`/model <名前>` と `/effort <段階>` は、モデルとエフォートのボタンと同じ切り替えになります。
  - 添付と補完は、対応している AI（いまは Claude）のプロジェクトでだけ出します。
- **ツールの表示**: 続けて呼ばれたツールは「✓ ツール 4件 Glob · Read · Bash 2」の1行にまとめて折りたたみ、押すと1件ずつの行を開きます（1件だけのときはその行をそのまま出します）。実行中は、いま動いているツールを同じ行に出します。
- **サブエージェント**（プロトコル v10）: AI が作業を任せた子のエージェント（Claude の `Agent` / `Task` ツール）は、本流には「◆ Explore 失敗テストの原因調査」の1行だけを出し、中身はペインの下側のサブペインに出します。
  - サブペインはサブエージェントごとのタブ（「状態 種類: 説明」）で切り替えます。中身は、渡した指示（既定は1行。押すと全文）、サブエージェントの発言とツール、作業中の表示です。本流の行を押すと、そのタブを開きます。
  - 新しいサブエージェントが動き出したら自動で開いてそのタブにし、全部終わったら中身を畳んでタブの帯だけ残します。帯の右の ∨ で開け閉め、× で閉じます（次のサブエージェントが動き出すとまた開きます）。開いたときに動いているものが無ければ出しません（本流の行から開けます）。
  - 本流とサブペインの境目はドラッグで高さを変えられます（ペインの高さに対する割合を端末に覚える。ダブルクリックで戻す）。
  - サブエージェントが出した許可要求・質問は本流に出し、上に「◆ 種類（説明）から」と添えます。そのタブと本流の行には `!` を付けます。
  - ペインが低い（本流とサブペインの領域が 360px 未満）ときは分けずに、本流の行の下に中身を埋め込みます（動いている間は開き、終わったら畳む）。iPhone では自動では開かず、本流の行を押すとサブペインを全面に重ねて出し、左上の ＜ で本流に戻ります。
- **新規セッション**: プロジェクトを選んで開始します。開始画面から新しいプロジェクトも作れます（6.3）。一覧の行とペインのヘッダーには「プロジェクト名 · マシン名」を出します（このPCのプロジェクトはマシン名を省きます）。
  - **空のセッションは残さない**: 最初の指示なしで始めて、何も書き込まずに閉じたセッション（名前が「新しいセッション」のまま）は Hub が消します。消すのは、ペインを閉じた・ペインを別のセッションに切り替えた（iPhone は詳細画面から離れた）とき、停止・アーカイブしたとき、Hub の起動時（前回の残り）です。送信するか名前を付ければ、空ではなくなります。
  - **AI が作ったセッション**: セッションの中の AI は、Hub の API で新しいセッションを作れます（6.8）。作られたセッションは、開いている端末で自動的に開きます（iPad / Web は新しいペイン、iPhone はその会話の画面）。
- **セッションのアーカイブと削除**（全端末共通。Claude のデスクトップアプリ・スマホアプリと同じ考え方）
  - 操作する場所: iPhone は一覧の行を左にスワイプして「アーカイブ」「削除」を出します。iPad / Web は、一覧の行の右クリック（iPad は長押し）とペインのヘッダーの「⋯」メニューから選びます。
  - **アーカイブ**: 一覧から外し、一覧の末尾の「アーカイブ済み（件数）」に畳んで入れます。履歴は残り、開いて読めます。「アーカイブを解除」で一覧に戻し、送信すれば続きから再開します。確認は挟まず、画面下に「元に戻す」を数秒出します。
  - **削除**: Hub の記録（会話とイベント）と、エージェント側の履歴（Driver が対応していれば）を消します。元に戻せないので、「このセッションを削除します。元に戻せません」と確認を1回挟みます。削除ボタンの文字はエラー色（`#f85149`）にします。
  - 実行中・許可待ち・質問待ちのセッションは、Hub がエージェントを止めてからアーカイブ・削除します。このときは確認で「実行中のセッションを止めます」と添えます。
  - アーカイブ・削除したセッションを開いているペインは、すべての端末で閉じます（ペインの並びの自動保存からも外します）。未読・待ちの件数とアプリアイコンのバッジも数え直します。
  - アーカイブ済みのセッションは、自動では削除しません。

### 5.1 ファイルビュワー

エージェントが作ったり変えたりしたファイル（HTML のスライド、画像、PDF、Markdown、ソースコード）を、PWA の中で見るための機能です（全端末共通）。Claude のデスクトップアプリで、チャット内のパスをクリックするとプレビューで開くのと同じ考え方です。開発用サーバー（`localhost:3000` など）のプレビューは扱いません（9）。

**開き方**
- 会話の中のファイルのパスをタップ（クリック）すると開きます。パスとして扱うのは次のものです。
  - ツールの行のうち、ファイルを対象にするもの（`Write`、`Edit`、`Read` など）。
  - 許可カードの変更ファイル（`FileChange.path`）の「開く」。いまのファイルを開きます。新しく作るファイル（`add`）は、許可するまで無いので出しません。
  - 返答の Markdown の中のインラインコードのうち、拡張子付きでプロジェクト内のパスに見えるもの（`slides/index.html` など。`src/a.ts:12` のような行番号は外して開く）。ビュワーで開いた Markdown の中も同じです。
- パスがプロジェクトのフォルダの外（Google ドライブなど 6.7 で認めるフォルダを除く）を指していたり、ファイルが無かったりしたときは、開かずに「ファイルを開けません: <理由>」とビュワーに出します。
- ツールの行のパスは、`tool` イベントの `paths`（プロトコル v5）を使います。`paths` が無いイベント（v4 以前の記録や、入れていない Driver）は、パスを取り出さず、開けない行として扱います。

**表示する場所**
- iPad / Web: セッションのペインの隣に「ビュワーのペイン」を開きます。ビュワーのペインもペインの1枚として並び、ペインの並びの自動保存に入ります（開いているファイルのパスも保存します）。同じセッションから別のファイルを開くと、そのセッションのビュワーのペインの中身を差し替えます（ペインを増やし続けないため）。
- iPhone: セッションの詳細の上に、全画面で重ねて開きます（`#/f/<セッションID>?path=…`）。左上の「閉じる」（戻る）で会話に戻ります。
- ヘッダーには、ファイル名（プロジェクトからの相対パス）、プロジェクト名と大きさ、「再読み込み」、「全画面」（HTML・PDF・画像・動画のとき）、「新しいタブで開く」（マウスのある端末のみ）、「閉じる」を置きます。iPad / Web では、ペインの「最大化」もあります（「全画面」とはアイコンを分ける）。

**ファイルの種類ごとの表示**

| 種類 | 拡張子の例 | 表示のしかた |
|---|---|---|
| HTML | `.html` `.htm` | サンドボックス付きの iframe で表示し、スクリプトも動かす（7）。同じフォルダの画像・CSS・JS は相対パスで読める |
| 画像 | `.png` `.jpg` `.gif` `.webp` `.svg` | `<img>` で表示。SVG も `<img>` で開き、中のスクリプトは動かさない |
| PDF | `.pdf` | ブラウザ内蔵の PDF 表示を iframe で使う。サンドボックスにすると内蔵の PDF 表示が動かないので、PDF だけはサンドボックスにしない（PDF の中身はブラウザ側で隔離される） |
| 動画・音声 | `.mp4` `.webm` `.mp3` | `<video>` / `<audio>` |
| Markdown | `.md` | 会話と同じ `react-markdown` + `remark-gfm` で表示。「ソースを表示」に切り替えられる |
| テキスト・ソース | 上記以外の文字のファイル | 行番号付きで、文字のまま表示（色分けは後で足す） |
| その他 | バイナリ | 「このファイルは表示できません」と、大きさと「ダウンロード」を出す |

- 文字のファイルとして表示するのは 2MB まで、それより大きいものは先頭だけを出し、「全体をダウンロード」を添えます。
- HTML のスライドを見るために、次のことに対応します。
  - 矢印キー・スワイプでのページ送り（スクリプトを動かすので、スライド側の操作がそのまま効く）。iframe にフォーカスを移すため、開いたときに iframe をフォーカスします。
  - 全画面: Web と iPad は iframe の全画面表示（`allowfullscreen`）を使います。iPhone の Safari は要素の全画面表示ができないので、ビュワーを画面いっぱいに広げてヘッダーを隠し、右上に小さな「全画面を終了」ボタンだけを出します（iframe の中のタップは外から受け取れないため、常に出しておく）。
  - reveal.js などを CDN から読むスライドは、端末がインターネットにつながっていればそのまま動きます。
  - できないこと: 中身は別のオリジン扱いなので、同じフォルダのファイルを `fetch()` で読むものや、`<script type="module">` で読むもの（Vite などでビルドした出力）は動きません。`/files/` に CORS を付けると、別のサイトのページからもファイルを読めてしまうためです。動かしたいときは、1つの HTML にまとめてもらうか、「新しいタブで開く」ではなく `tailscale serve` で公開して見ます。
- 動画: iPhone / iPad の Safari は Range で読めないと動画を再生しないため、`/files/` は Range に対応します。
- 再読み込み: 自動では読み直しません。ヘッダーの「再読み込み」で読み直します。開いているファイルが同じセッションの `Write` / `Edit` で変わったときは、「再読み込み」の横に青（`#4493f8`）の点を付けて知らせます。

## 6. プロジェクトとマシン

### 6.1 用語

| 用語 | 中身 |
|---|---|
| マシン | CLI（`claude` / `codex`）が動く場所。接続方法は `local`（Hub と同じPC）と `ssh`。後で `runner` を足せるようにしておく |
| プロジェクト | マシン＋そのマシン上のフォルダ＋使う AI（Claude / Codex のどちらかに固定）＋名前＋設定 |
| セッション | 必ず1つのプロジェクトに属する |

これまでの「フォルダの許可リスト」は、プロジェクトに置き換えます。セッションは、登録したプロジェクトでだけ起動できます。

### 6.2 マシン

- 持つ項目: ID（Hub が採番し、変えない）、表示名、接続方法（`local` / `ssh`）、SSH のホスト名、OS（`windows` / `linux` / `macos`）、プロジェクトを作ってよいルートフォルダ（複数可）、CLI の起動コマンド（省略時は既定値）。
- ID と接続方法を分けて持つのは、Hub を別のPCへ移すためです（6.5）。プロジェクトとセッションはマシンの ID だけを持ち、接続方法は持ちません。
- SSH は、Hub のPCの OpenSSH クライアント（Windows 標準の `ssh.exe`）を使います。
  - ホストは `~/.ssh/config` の `Host` 名で指定します。認証は鍵と ssh-agent だけにし、Hub はパスワードや秘密鍵を保存しません。
  - `BatchMode=yes` を付け、パスワードやホスト鍵の確認を求められたら失敗させます。ホスト鍵の確認は省きません。初めてのホストは、ユーザーがターミナルで一度 `ssh` して登録します。
  - `ServerAliveInterval` を付けて、切断を早く検知します。
- 接続の確認: Hub はマシンごとに、つながるか、CLI があるか、ログイン済みか（`checkAuth`）を確かめ、マシンの一覧に「● 接続中」「● 未ログイン」のように示します。
- パスは、マシンの OS に合わせて扱います。Hub が Windows でも、Linux のマシンのパスは POSIX として扱います（`path.posix`）。

### 6.3 プロジェクト

- 持つ項目: ID、名前、マシンの ID、フォルダ（そのマシン上の絶対パス）、使う AI（`claude` / `codex`。プロジェクトごとに固定。フォルダと AI の組で1つのプロジェクトなので、同じフォルダを AI ごとに1つずつ登録できる）、`full_auto` を許すか、既定の権限モード。
- MVP では、Hub の設定ファイルの `folders` がプロジェクトにあたります（マシンはこのPCだけ）。フェーズ3で保存先を SQLite に移します。そのとき `folders` は読み込んで移します。
- 先行して、このPCでは画面から作れます（作り方は「既存のフォルダを選ぶ」と「新しいフォルダを作る」。`git clone` と SSH 先のマシンはまだ）。ルートフォルダは設定ファイルの `projectRoots` に書き、作ったプロジェクトは Hub が `folders` に書き足します（API は `GET /api/fs/dirs` と `POST /api/projects`、型は packages/hub/src/api.ts）。
- 一覧の並び順は `folders` の順で、全端末で共有します。設定タブの「プロジェクト」の ↑↓ と、iPad / Web の左の一覧でプロジェクト名をドラッグして変えられます。Hub は設定ファイルの `folders` の順だけを入れ替えます（`PUT /api/projects/order`。登録済みのプロジェクトをすべて `{ path, agent }` で新しい順に渡し、過不足があれば 409）。登録外のプロジェクトは並べ替えず、名前順で最後に出します。
- プロジェクトには色を付けられます（`folders` の `color`。`red` / `orange` / `yellow` / `green` / `teal` / `blue` / `purple` / `pink` / `gray` のパレットから選ぶ。省略時は色なし）。設定タブの「プロジェクト」で選ぶと、Hub が設定ファイルのその項目の `color` だけを書き換え（`PATCH /api/projects`、本文は `{ path, color }`。`null` で外す）、全端末で共有します。色を付けたプロジェクトは、セッションのペインの見出し（iPhone では会話画面の見出し）を左端の帯とその色の薄い塗りで示し、一覧のプロジェクト名の横に色見本を出します。
- 作る場所: 設定タブの「プロジェクト」と、新規セッションの開始画面。
- 作る手順:
  1. マシンを選ぶ（接続状態を ● で示す。つながらないマシンは選べない）
  2. 作り方を選ぶ
     - 既存のフォルダを選ぶ: マシンのルートフォルダの下を、Hub 経由で見て回って選ぶ
     - 新しいフォルダを作る: 名前を入れて作る。`git init` も選べる
     - `git clone`: URL を入れて、ルートフォルダの下に clone する
  3. 名前、使う AI、設定（`full_auto` を許すか、既定の権限モード）を決める。使う AI は、そのマシンで CLI が使えてログイン済みのものだけ選べる
- フォルダは、マシンのルートフォルダの下にあるものだけ使えます。Hub は、パスの正規化とシンボリックリンクの解決をしたうえで、ルートの外に出ていないかを、そのマシン上で確かめます。
- プロジェクトを外すと、そのプロジェクトのセッションはすべてアーカイブします。フォルダとエージェント側の履歴は消しません。

### 6.4 SSH 先での実行

- CLI は SSH 先で動かします。CLI の Bash やテストを SSH 先で動かすためです（このPCで CLI を動かして、ファイルだけを SSH で触る方式は採りません）。
- Hub は `ssh -T <host> -- <起動コマンド>` を子プロセスとして起動し、その標準入出力を Driver に渡します。Claude の stream-json も Codex app-server の JSON-RPC も標準入出力でやりとりするので、Driver は SSH を意識しません。
  - 起動コマンドは、作業フォルダへ移ってから CLI を起動します（`cd <フォルダ> && exec claude …`。値はシェル用に必ずクォートする）。
  - SSH の非対話シェルでは `~/.bashrc` の PATH が読まれないことがあるため、既定ではログインシェル（`bash -lc`）で起動します。CLI の場所はマシンの設定で直接指定することもできます。
- ログイン: CLI は、そのマシンでログインした状態を使います。サブスクリプション前提（API キーを使わない）は SSH 先でも同じで、`checkAuth()` は SSH 先で実行します。
  - 最初に使う Ubuntu のマシンは、Codex はログイン済みです。Claude は、`claude` を入れて一度ログインしておく必要があります。
- 許可要求: Hub 内の MCP ツールには SSH 先の CLI から届かないため、Claude の許可要求は標準入出力の制御メッセージで受けます（docs/protocol.md の Claude の対応表）。ローカルでも同じ方式にそろえます。
- 切断: SSH が切れると CLI も終わります。Driver は `error`（`fatal: false`）と `status: stopped` を送ります。次に送信したとき、Hub が `resumeToken` で再開します（会話の履歴は SSH 先に残っています）。実行中のターンは切断で途切れます。長時間の作業で困るようなら、後で Runner（常駐プロセス）を足します。
- 履歴の削除（`deleteHistory`）は SSH 先のファイルを消すので、これも起動役を通して実行します。

### 6.5 Hub の置き場所と移設

- 当面、Hub はこのPC（常時起動）に置きます。将来、別のPCへ移せるようにしておきます。
- 移せるようにするための決まり:
  - Hub の状態（SQLite、設定、VAPID 鍵）は、1つのデータフォルダにまとめます。場所は環境変数で変えられるようにし、移設はこのフォルダのコピーで行います。
  - Hub のコードには、このPC固有のパスや Windows 前提を入れません。
  - マシンの接続方法だけを変えれば移せるようにします。移設後は、新しい Hub のPCを `local` に、元のPCを `ssh` に切り替えます（元のPCが Windows なら OpenSSH サーバーを有効にします）。プロジェクトとセッションはそのまま使えます。
- 移設で変わるもの: PWA の URL（`tailscale serve` のホスト名）が変わるので、ホーム画面の PWA を入れ直し、Web Push の通知を許可し直します。
- Hub を複数置いて同期することはしません。PWA の接続先は常に1つです。

### 6.6 共通プロトコルへの変更案（起動役、未反映）

`packages/shared` を変えます。反映したら docs/protocol.md の変更履歴に追記します。

- Driver に「起動役（`ProcessLauncher`）」を渡します。起動役は `local` なら `child_process`、`ssh` なら `ssh` で子プロセスを起動し、標準入出力を返します。Driver は子プロセスを自分で起動せず、必ず起動役を使います。
- `checkAuth`、`start`、`deleteHistory` に起動役を渡します（`checkAuth` はマシンごとに呼ぶことになります）。
- 起動役は OS（パスの扱い）も Driver に知らせます。
- docs/protocol.md の「フォルダの許可リスト」という言い方を「プロジェクト」に改めます。
- Codex への依頼: `driver-codex` で、子プロセスの起動を起動役に置き換えてください。

### 6.7 ファイルの配信（ファイルビュワー用）

- Hub は、セッションのプロジェクトのフォルダの下にあるファイルを、次の形で返します。
  - `GET /files/<セッションID>/<プロジェクトからの相対パス>`: ファイルの中身をそのまま返します。HTML の中の相対パス（`img/a.png` など）がそのまま解決できるように、クエリではなくパスで指定します。
  - `GET /api/sessions/<セッションID>/file-info?path=<相対パス>`: 大きさ、更新時刻、種類（`html` / `image` / `pdf` / `media` / `markdown` / `text` / `binary`）を返します。Web はこれを見て表示のしかたを決めます。
- プロジェクトのフォルダの外でも、次のフォルダの下のファイルは返します（絶対パスで指定する。`file-info` の `path` も絶対パス（区切りは `/`）で返し、Web はそれを `/files/<セッションID>/G%3A/…` の形の URL に使う）。
  - パソコン版 Google ドライブ（Windows）。直下に「マイドライブ」（`My Drive`）があるドライブ（`G:\` など。共有ドライブも含む）と、ミラーリングの `~/マイドライブ`。Hub が1分ごとに探し直します。
  - 設定ファイルの `viewerRoots`（絶対パスの配列）に書いたフォルダ。
- 返してよいのは、プロジェクトのフォルダと上のフォルダの下のファイルだけです。Hub はパスの正規化とシンボリックリンクの解決をしたうえで、フォルダの外に出ていないかを確かめます（`..` や別のドライブ・UNC パスで外に出るものは拒否。ツールの `paths` は絶対パスで届くので、フォルダの下を指す絶対パスは受け付ける）。フォルダの一覧（ディレクトリの中身）は返しません。
- アーカイブしたセッションのファイルも見られます。削除したセッションの URL は 404 にします。
- `Content-Type` は拡張子から決め、`X-Content-Type-Options: nosniff` を付けます。`Cache-Control: no-store` にして、再読み込みで必ず最新を取ります。
- MVP では `local` のマシンだけに対応し、Hub が直接ファイルを読みます。SSH のマシン（フェーズ3）では、起動役を通してそのマシン上で読みます（パスの確認もそのマシン上で行う）。
- 今は MVP にプロジェクトの ID が無いため、セッションの ID で指定します。プロジェクトを SQLite に移すとき（6.3）に、`/files/<プロジェクトID>/…` に変えるかを決めます。

### 6.8 AI からのセッション作成

- Hub は起動時に自分の URL（`http://127.0.0.1:<port>`）を環境変数 `AGENTPWA_HUB_URL` に入れます。子プロセスはこれを引き継ぎます。
- Claude の Driver は、CLI に `AGENTPWA_SESSION_ID`（Hub のセッション ID）を渡し、`--append-system-prompt` で作り方（下の `curl`）を伝えます（`packages/driver-claude/src/hub-guide.ts`）。
- AI は `POST $AGENTPWA_HUB_URL/api/sessions` に `X-AgentPWA-Session: $AGENTPWA_SESSION_ID` を付けて送ります。本文は Web と同じ `CreateSessionRequest` で、`cwd` を省くと作成元と同じプロジェクトになります。Hub は作成元を `parentSessionId` として記録し、Web は `parentSessionId` 付きで新しく届いたセッションを自動で開きます。
- 作成元が「すべて自動」でなければ、「すべて自動」のセッションは作れません（AI が確認を減らす抜け道にしないため）。プロジェクトの許可リストと `allowFullAuto` の確認は、Web から作るときと同じです。
- このPCからの直接のリクエストになるので、設定ファイルの `allowLocalhost` が `true`（既定）である必要があります。
- Codex への依頼: `driver-codex` でも、子プロセスに `AGENTPWA_SESSION_ID` を渡し、作り方を指示に足してください（`hub-guide.ts` の `withHubEnv` と `hubGuide` と同じ内容）。

## 7. セキュリティ

- Hub は `127.0.0.1` でのみ待ち受け、`tailscale serve` が中継します。
- serve が付ける `Tailscale-User-Login` ヘッダーを確認し、許可したユーザー（設定ファイルの `allowedUsers`）以外は拒否します。
  - `allowedUsers` が空なら、Hub の起動時と `npm run setup` で、このPCにログインしている Tailscale ユーザー（`tailscale status --json` の自分のログイン名）を入れます。このPCの持ち主とみなします。
  - 許可されていないユーザーが開こうとすると、Hub はそのユーザーを「許可待ち」としてメモリに覚え（20件まで。再起動で消える）、設定タブの「アクセス」に出します。許可された端末か、このPCのブラウザ（127.0.0.1）から「許可」すると `allowedUsers` に書き足します（`POST /api/access/allow`。取り消しは `/api/access/revoke`、許可待ちから外すのは `/api/access/dismiss`）。許可されていないユーザーは API に届かないので、自分を許可することはできません。自分自身の許可は取り消せません。
  - 許可されていないユーザーには、理由と次にやることを書いたページを返します（ブラウザの画面遷移のとき。PWA は画面をキャッシュから出すので、Web の側でも `/api/info` の 401 / 403 を見て同じ説明を出します）。
- Tailscale の ACL で、Hub のポートに届く端末を自分の端末に限定します。
- セッションは、登録したプロジェクトでだけ起動します。プロジェクトのフォルダは、マシンごとに決めたルートフォルダの下に限ります（6.3）。
- SSH は鍵認証だけを使い、Hub はパスワードと秘密鍵を保存しません。ホスト鍵の確認は省きません（6.2）。
- 権限モードの既定は「自動承認」（`auto`）です（プロジェクトごとに設定ファイルの `defaultPermissionMode` で変えられます）。危険と判定された操作はエージェント側で止まります。
- 「すべて自動」（`full_auto`）は、プロジェクトの設定で個別に許可したプロジェクトだけで使えます。Hub がこの制限を守り、許可のないセッションへの切り替えは拒否します。
- 「自動承認」（`auto`）は、危険と判定された操作をエージェント側で止めるため、フォルダの制限を設けません。
- 削除はエージェント側の履歴も消し、元に戻せません。Hub の削除 API は1件ずつ受け付け、一括削除は作りません。
- **ファイルビュワーの HTML**（5.1、6.7）: エージェントが作った HTML のスクリプトを、Hub と同じホスト名で動かすことになります。Hub の利用者確認は Tailscale のヘッダー（端末ごとに付く）なので、何もしないと、HTML の中のスクリプトから Hub の API を呼べてしまいます（指示の送信、許可の操作、`/ws` への接続など）。次の3つで防ぎます。
  - iframe は `sandbox="allow-scripts allow-popups"` だけにし、`allow-same-origin` は付けません。中身は別のオリジン扱いになり、PWA の画面や保存データには触れません。`/files/` の応答にも `Content-Security-Policy: sandbox allow-scripts allow-popups` を付け、URL を直接開いたとき（「新しいタブで開く」）も同じ制限にします（PDF だけは除く。5.1 の表）。PWA の Service Worker は `/files/` に index.html を返さないようにします。
  - Hub は、`/api/` の GET 以外のリクエストと `/ws` への接続で `Origin` ヘッダーを確かめ、PWA 自身のオリジン（serve のホスト名）以外は 403 にします。`Origin` が `null`（サンドボックスの iframe から）のものも拒否します。本文のある `/api/` のリクエストは `application/json` だけを受け付けます。
  - `/api/` の GET の応答には CORS のヘッダーを付けません（別のオリジンからは読めない）。
- オリジンを完全に分けたい場合は、ファイルの配信だけを別のポートで待ち受け、`tailscale serve` で別に公開する方法もあります。設定が1つ増えるので、MVP では上の3つで足りるものとし、必要になったら移します。

## 8. フェーズ

1. **MVP**: このPCのみ。Claude と Codex それぞれで、複数セッション・優先表示・許可操作ができる。iPhone 表示と、iPad/Web の複数ペイン表示。ペインの並びは端末ごとに自動保存し、次に開いたときに復元する。セッションは最初からプロジェクト（`local` のマシンだけ）で起動し、Driver も起動役を通して子プロセスを起動する（後で SSH を足すときに作り直さないため）。
2. Web Push、再起動後の再開、差分表示、ファイルビュワー（5.1。`local` のマシンだけ）
3. SSH のマシンとプロジェクトの管理画面（作成・`git init`・`git clone`）
4. 常駐化
5. Runner（SSH の切断で困るようになったら）

## 9. 見送った機能

- **ワークスペース**（ペインの並びと各ペインのセッションに名前を付けて保存し、切り替える機能）は MVP に入れない。必要になったら追加する。
- **開発用サーバーのプレビュー**（エージェントが起動した `localhost:<ポート>` のアプリを PWA の中で見る機能。Claude のデスクトップアプリのブラウザのペインにあたる）は入れない。iPhone / iPad から届かせるには Hub がポートを中継する必要があり、中継先の制限とオリジンの分離を別に設計しなければならないため。必要なら、当面は `tailscale serve` でそのポートを一時的に公開して見る。
- **ファイルビュワーでの編集**と**フォルダの一覧（ファイルツリー）**は入れない。見るだけにし、変更はエージェントに頼む。

## 10. デザインの決まり

- 配色は GitHub の Primer（`@primer/primitives` 11.10.0）の dark テーマのトークン値を使う。

| 用途 | 値 |
|---|---|
| 背景（本文） | `#0d1117`（bgColor-default） |
| 背景（ヘッダー・サイドバー・ユーザー発言） | `#151b23`（bgColor-muted） |
| 背景（入力欄・コード） | `#010409`（bgColor-inset） |
| 通常ボタン | 背景 `#212830`、枠 `#3d444d` |
| 主ボタン（許可・送信・開始） | 背景 `#238636`、文字 `#ffffff` |
| 境界線 | `#3d444d` |
| 文字 | `#f0f6fc`、補助 `#9198a1` |
| 許可／承認待ち | `#d29922`、強調面 `#bb800926`、枠 `#9e6a03` |
| 質問 | `#ab7df8` |
| 完了・未読 | `#4493f8` |
| 実行中 | `#3fb950` |
| エラー・削除行 | `#f85149` |
| Claude の識別色 | `#db6d28` |
| Codex の識別色 | `#4493f8` |

- 形はシンプルにする。角丸は、ボタン・入力欄・コード枠など操作部品だけに 6px（件数バッジは 3px）を使い、一覧・ペイン・パネルは角丸なしにする。
- 影、グラデーション、丸いピル型のラベルは使わない。状態は「● 許可待ち」のように、色付きの点と文字で表す。
- 一覧はカードを並べず、区切り線のある行で表示する（VS Code のサイドバーに近い密度）。
- 待っているペインは、ヘッダー上端に 2px の黄色の線を引いて示す（VS Code のアクティブタブと同じ表現）。
